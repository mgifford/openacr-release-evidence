# Report information architecture

**Status: Phases 3–5 implemented; Phase 6 proposed.**

The release report remains static, no-JavaScript HTML generated by
`src/acr_evidence/report.py`. This page records the structure now in use and the
URL/anchor compatibility rules.

## Implemented page structure (Phase 3)

Each target directory now writes six pages:

| Page | Purpose | Contains |
| --- | --- | --- |
| `index.html` | Overview | Header, plain-language summary, "How to read this report", summary metrics, "Explore the report", compatibility links |
| `issues.html` | Reported issues | Component index, issue index, canonical issue records, verification gaps |
| `criteria.html` | WCAG criteria | Criterion index and per-criterion issue lists |
| `sources.html` | Sources and data | Exact-release component inventory, changes since the previous target, lineage records, assessment scope, external reproduction evidence, provenance and downloads |
| `method.html` | How this report works | Why this report is different, method, limitations |
| `acr.html` | Draft ACR | Standards-shaped ACR narrative for human review (already separate) |

A consistent page navigation appears on every page. The current page is marked
with `aria-current="page"`. The report header, support banner and footer are
shared. The breadcrumb on subpages links back to the report overview.

### What moved

| Content | Before | After |
| --- | --- | --- |
| Plain-language summary, terminology, counts | One long `index.html` | `index.html` |
| Issue index and canonical issue records | One long `index.html` | `issues.html` |
| Component index | One long `index.html` | `issues.html` |
| Verification gaps | One long `index.html` | `issues.html` |
| WCAG criterion sections | One long `index.html` | `criteria.html` |
| Assessment scope and complete metadata | One long `index.html` | `sources.html` |
| Component inventory | Not present on report page | `sources.html` |
| Component changes and lineage | Not present on report page | `sources.html` |
| Reproduction evidence | One long `index.html` | `sources.html` |
| Provenance and downloads | One long `index.html` | `sources.html` |
| Why this is different, method, limitations | One long `index.html` | `method.html` |

`index.html` is now about 60 KB for the beta2 snapshot instead of about 1 MB.
`issues.html` remains large because it contains every canonical issue record;
splitting individual issue records into separate pages is a later optimisation,
not a prerequisite for understanding the report.

## Why this order

The reviewer feedback said methodology, source data and issue inventories were
competing for attention, and that the report was too long to know how to act on.
The overview now answers "what do we know and what should I do?" before any
methodology. The issue and criterion pages hold the investigation detail. The
source page is the audit trail. The method page is shared methodology rather than
a preamble to every release.

The ACR remains a distinct standards-shaped output. It is never merged into the
plain-language overview.

## Component history view

`sources.html` now includes:

- **Component inventory** — every bundled module and theme with status,
  standard-profile installation, default/admin theme role and package.
- **Component changes** — added, removed and status/default changes compared
  with the previous declared target that has a committed inventory. For
  12.0.0-beta2 this compares with 12.0.0-alpha1; for 11.4.12 it compares with
  10.6.21.
- **Component lineage** — the curated Olivero/Claro/Gin/Default Admin records,
  with a per-release state such as “Still bundled; removal recorded for
  12.0.0-beta1” or “Removed from Core in 12.0.0-beta1”.

The sections state explicitly that package membership is not a fix, that removal
does not resolve issues, and that adoption does not inherit predecessor issues.
The lineage records remain `unreviewed`.

## Issue grouping and filter

`issues.html` groups every issue by the stored applicability value, not by manual
ordering:

1. Verified problems
2. Probably affects this release
3. Fix included, not behaviourally verified
4. Needs checking
5. Not present or outside this report

Each group has its own heading, count, explanation and table. Empty groups keep a
short empty-state message instead of an empty table.

A CSS-only radio filter hides the groups that do not match the selected
applicability. All groups remain in the document; browsers without `:has()`
support show all of them, and the page explains this. The filter does not need
JavaScript.

The "Why are these not determined?" box is generated from the findings. For
12.0.0-beta2 it reports 402 not-yet-determined issues: 394 basic metadata
records and 8 issues reported after the release was cut. Those counts come from
the stored evidence, not editorial estimates.

## Stable URLs and anchors

Current stable paths:

- `reports/index.html` — release index.
- `reports/matrix.html` — complete cross-release matrix.
- `reports/<target>/index.html` — release overview.
- `reports/<target>/issues.html` — reported issues.
- `reports/<target>/criteria.html` — WCAG criterion evidence.
- `reports/<target>/sources.html` — sources, inventory, provenance.
- `reports/<target>/method.html` — method and limitations.
- `reports/<target>/acr.html`, `acr.md` — draft ACR.
- `reports/<target>/evidence.json`, `summary.json`,
  `criterion-evidence.json`, `reproduction-evidence.json`,
  `openacr.yaml`, `openacr-validation.json` — machine-readable outputs.
- `reports/drupal-core-atag/` — ATAG evidence, separate from WCAG.

Anchors added in this phase:

- `#summary` — plain-language summary.
- `#how-to-read` — terminology.
- `#summary-details` — counts.
- `#issues` / `#issue-index-heading` — issue table.
- `#gaps` — verification needs.
- `#scope` — release details.
- `#method` — method and limitations.
- `#provenance` — downloads and digests.

Every in-page anchor is checked by `tests/test_report.py` against ids in the
rendered HTML.

## Reader paths

| Reader | First stop | Next |
| --- | --- | --- |
| Drupal maintainer | Summary and "What to do next" | Issues marked "probably affects this release"; then the issue's "What to do next" |
| Site builder | Summary component scope | Component index; check whether the affected module or theme is installed |
| Accessibility evaluator | "How to read this report" | Issue index, source links, criterion evidence, reproduction evidence |
| Procurement reviewer | Summary and draft banner | "Why this report is different"; draft ACR; known limitations |
| Project maintainer | Method and provenance | Digests, source timestamps, component inventory, tests |

## What is intentionally not on the overview

- A single accessibility score or percentage.
- A conformance result derived from issue counts.
- A severity rating for issues. Tracker priority is retained in the data but is
  not presented as an accessibility grade.
- A claim that a removed component's issues were fixed.
- A claim that an adopted component's predecessor issues automatically apply.

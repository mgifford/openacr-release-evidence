# Generated evidence reports

Each target also contains `openacr.yaml` and `openacr-validation.json`. The YAML
is a schema- and catalog-validated OpenACR draft with no conformance values; it
requires human completion and `openacr-validate --strict` before publication.
The current drafts were also checked with the official `@civicactions/openacr`
0.3.11 CLI (`Valid!`).

`index.html` is the Pages landing page and cross-release matrix. It links to
each target directory and to the machine-readable evidence. The Pages workflow
deploys this landing page plus each report's `index.html`, `report.css`,
`evidence.json` and `summary.json`; it does not publish `collection.json`,
`analysis.json` or raw snapshots.

The multi-target reports are generated with:

```sh
acr-evidence collect --manifest config/drupal-core-11.4.12.json --output reports/collection.json
acr-evidence multi --collection reports/collection.json   --targets config/drupal-core-targets.json --output reports
```

The weekly workflow runs the same commands and opens a review PR; it does not
publish automatically.

`drupal-core-11.4.12/` was generated by:

```sh
acr-evidence pipeline \
  --manifest config/drupal-core-11.4.12.json \
  --release 11.4.12 \
  --output reports/drupal-core-11.4.12
```

It contains normalized public evidence, the applicability analysis, and a
static, no-JavaScript HTML report. It is a **draft evidence report, not an
Accessibility Conformance Report**.

- Do not hand-edit generated files; change the manifest, source code or fixtures
  and regenerate.
- Raw CLI/API payloads are under `private-evidence/` and are not part of this
  report.
- Publication to GitHub Pages requires human approval (see `GOVERNANCE.md`).
- The `evidence.json` digest is reproducible from the published artifact; see
  `docs/EVIDENCE-MODEL.md`.

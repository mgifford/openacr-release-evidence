What this report says about Drupal Core 12.0.0-beta2

This report tracks accessibility issues reported against Drupal Core and asks whether they affect 12.0.0-beta2. It is a starting point for investigation, not an accessibility certification.

We collected 432 active accessibility issues. 30 issues probably affect this release, 0 issues are verified problems in this release, and 402 issues are not yet determined.

No reported problem has been reproduced against this release, so the report cannot call any issue a verified problem. No fix has been tested and confirmed to resolve a barrier in this release.

What we actually know

  • 30 issues probably affect this release based on reports and code checks, but were not reproduced.
  • 402 issues are not yet determined. That means we have not checked whether they affect this release; it does not mean the release is accessible or inaccessible.
  • 0 issues have been reproduced on this release.
  • 0 findings have a fix included in the release; inclusion is not proof that the barrier is gone.

Component scope in this release

This exact release bundles 67 modules and 3 themes. The standard installation profile enables 36 modules and 1 theme; its default theme is default_admin and its admin theme is default_admin. Bundled, installed and default-installed components are different scopes. Claro left Core in 12.0.0-beta1 and is now maintained as the Claro contributed project. Its absence from this release is a scope change, not evidence that its reported barriers were fixed. Olivero left Core in 12.0.0-beta1 and is now maintained as the Olivero contributed project. Its absence from this release is a scope change, not evidence that its reported barriers were fixed. Default_admin was adopted from the Gin contributed project. Adoption does not automatically make every predecessor issue applicable; each issue needs its own release evidence.

See the component inventory, changes and lineage.

What to do next

If you maintain Drupal Core

Start with the issues marked “probably affect this release” and try to reproduce them on the exact release. Then check whether any fix commit is included and test its behaviour.

If you build Drupal sites

Check which modules and themes your site uses. A reported issue only matters to your site if the affected component is present and enabled.

If you evaluate accessibility

Use the issue list to plan testing. It is not a substitute for testing pages, interactions and assistive-technology use.

If you are buying or procuring

Treat this as a risk and question list, not an approved Accessibility Conformance Report. Ask vendors for a reviewed ACR for the exact product and version.

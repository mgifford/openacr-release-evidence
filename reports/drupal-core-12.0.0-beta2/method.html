Why this is different

A VPAT is a template; a completed report is an ACR. Most vendor ACRs are periodic, sample-based snapshots reviewed by legal or product management, with the vendor issue queue kept separate. This report is an issue-queue attestation: it is generated from the full active Drupal Core Accessibility queue and keeps every cited issue linked. It is stronger on known-report completeness, traceability and recency; it is weaker on independent page sampling and manual assistive-technology coverage.

This is not a WCAG-EM evaluation, a certification or a substitute for a procurement-specific ACR. A missing tagged issue is not evidence of support. Read the queue as reported barrier evidence and confirm every criterion with a reviewer.

Background: GSA OpenACR issue #180 · Drupal ACR process · WCAG-EM 2.0.

Method and limitations

  1. Paged the complete Drupal Core Accessibility queue (taxonomy term 1101) and kept only active review-relevant statuses: Active, Needs review, Needs work, RTBC and Patch. Fixed and closed issues are excluded.
  2. For a review-priority subset, retrieved the issue, its public comments and every merge request state through drupalorg-cli JSON output. Merged and closed MRs are included. The remaining active issues are complete inventory records (source, status, tags, component, version) with comments, MRs and commit history marked as not collected.
  3. Built a commit index for the target release branch and adjacent development branches, matched commit messages to issue IDs, and checked whether each commit is contained in the release tag using the public GitLab API.
  4. Applied documented classification rules. A tracker report is not a reproduction; commit inclusion is not behavioural verification; a closed issue is not proof of a release fix.
  5. Did not use AI, did not infer conformance and did not assign a percentage or score.

Discovery and tag resolution use the public Drupal.org API. Git containment uses git.drupalcode.org. The manifest records the declared configuration for this report; the stock installation profile is a separate scope. See the release details for exact component counts.

Theme availability for 12.0.x: front-end themes none recorded; admin themes default_admin. Removed in this line: olivero, claro. The core collection does not include the theme project queues; a theme ACR must cover those issues.

Limitations

  • The report covers active review-relevant issues carrying the Accessibility tag; it is not a census of every barrier. Closed and fixed issues are excluded by policy. Some active issues are metadata-only inventory records; their commit/comment evidence was not collected in this snapshot.
  • No issue was reproduced against an installed release in this phase. No screen-reader, keyboard, zoom, reduced-motion or forced-colors testing of the assessed release is claimed.
  • Commit matching relies on issue numbers in commit messages. Commits that omit the issue number, or fixes delivered by configuration or contributed modules, are not matched.
  • Commit containment is code inclusion, not proof that the barrier is behaviourally corrected.
  • WCAG criterion tags are candidate relevance signals, not conformance determinations.
  • An issue may describe a barrier that is fixed by a later release or by a downstream distribution; this report does not transfer those conclusions.

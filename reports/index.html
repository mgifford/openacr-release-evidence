Project responsibility and parent ACRs

Drupal Core is the top-level product in this snapshot. Themes, recipes and distributions can publish their own ACRs and point to a parent Core ACR, which makes responsibility visible without copying Core conclusions into a downstream product. In particular, Claro and Olivero are core themes in the 10.x/11.x targets and contributed projects in the 12.x targets; they should have separate ACRs that reference the matching Core release rather than being silently folded into Core.

The current pipeline records a parent_project field and displays it, but it does not yet collect contributed-project queues or generate parent-linked ACRs. Drupal CMS and LocalGov Drupal need their own manifests, Composer locks and parent references.

What this site publishes

Only an explicit allowlist is deployed: this landing page, each report HTML and stylesheet, evidence.json and summary.json. Raw CLI responses, private evidence snapshots, collection.json and analysis.json are not published.

Limitations

  • The sample is purposive, not a census. It is a set of Accessibility-tagged issues, not all barriers.
  • No issue in this snapshot was reproduced against an installed target. Commit inclusion is not behavioural verification, and a closed issue is not proof of a release fix.
  • The generic Admin theme component is shared across release lines with different admin themes (Claro in 10.6/12 alpha; Default Admin in 11.4/12 beta/main). Reproduce before applying a finding across a theme boundary.
  • Pre-release and development targets are not supported releases. Drupal 10.x is expected to reach end of life when Drupal 12.0.0 is released; verify the current policy.
  • WCAG tags are candidate relevance signals, not conformance determinations.
